# Единое ТЗ (SDD) — «Музыкальный»

**Версия:** 1.2  
**Дата:** 2026-09-25  
**Статус:** MVP  
**Назначение документа:** описать бизнес-логику продукта без углубления в техническую реализацию.

---

## 1. Назначение продукта

«Музыкальный» — локальное приложение для пользователя, который хранит музыкальные лайки в SoundCloud и хочет перенести их в личную коллекцию:

- скачать понравившиеся треки из SoundCloud на компьютер;
- вести учёт уже обработанных треков, чтобы не скачивать и не отправлять одно и то же повторно;
- при необходимости загрузить скачанные треки в выбранный плейлист Яндекс Музыки;
- видеть понятный прогресс, ошибки и текущий статус библиотеки.

Основная ценность MVP — убрать ручную работу: поиск новых лайков, скачивание каждого трека, проверку дублей и ручную загрузку в Яндекс Музыку.

---

## 2. Пользователь и основной результат

Основной пользователь — владелец аккаунта SoundCloud и аккаунта Яндекс Музыки, который работает с приложением на своём компьютере.

После настройки пользователь должен понимать:

- сколько треков уже считается загруженными в Яндекс Музыку;
- сколько треков скачано локально, но ещё не отмечено как загруженные в Яндекс Музыку;
- сколько новых треков найдено в лайках SoundCloud;
- какие треки пропали из текущего списка лайков, но уже были учтены приложением.

Пользователь должен иметь возможность выбрать нужные треки и выполнить действие: скачать, скачать и загрузить в Яндекс Музыку, только загрузить уже скачанное, либо вручную отметить треки как уже добавленные в Яндекс Музыку.

---

## 3. Состав MVP

### 3.1 Настройки

В MVP пользователь задаёт:

- имя пользователя SoundCloud или ссылку на страницу лайков;
- ссылку на плейлист Яндекс Музыки, если нужна загрузка в Яндекс Музыку;
- локальную папку для сохранения музыки через настройки проекта;
- формат и качество сохраняемых аудиофайлов через настройки проекта.

Для загрузки в Яндекс Музыку пользователь должен быть авторизован в Яндекс Музыке в Google Chrome на той же машине.

### 3.2 Просмотр библиотеки

Приложение показывает локально учтённые треки и сводные показатели по статусам. Список доступен после загрузки интерфейса и обновляется после операций.

Для работы со списком пользователь может:

- искать треки по названию и исполнителю;
- фильтровать список по всем трекам, новым трекам и трекам, которые ещё не считаются загруженными в Яндекс Музыку;
- выбирать один, несколько или все видимые треки;
- открыть локальную папку с музыкой.

### 3.3 Проверка новых лайков SoundCloud

Пользователь запускает проверку лайков SoundCloud. Приложение получает текущий список лайкнутых треков и сравнивает его с локальным учётом.

Результат проверки:

- новые треки добавляются в список как ожидающие обработки;
- уже скачанные или уже отмеченные как загруженные треки сохраняют свой статус;
- треки, которые ранее ожидали обработки, но больше не найдены в текущих лайках, получают статус «пропал из лайков»;
- пользователь видит количество новых, уже известных и пропавших из лайков треков;
- если SoundCloud вернул пустой список лайков или проверка ограничена настройкой максимального числа треков, статусы «пропал из лайков» не выставляются — неполный список не считается доказательством удаления лайка.

### 3.4 Скачивание треков

Пользователь выбирает треки и запускает скачивание.

Бизнес-правила скачивания:

- скачиваются только выбранные пользователем треки;
- скачивание работает по локальному учёту треков: повторная проверка лайков после перезапуска приложения не требуется;
- треки, защищённые DRM (контент SoundCloud Go+), скачать нельзя — пользователь видит понятную причину ошибки;
- если для выбранного трека уже есть локальный файл, повторное скачивание не требуется;
- успешно сохранённый файл переводит трек в статус «на диске», если он ранее не был отмечен как загруженный в Яндекс Музыку;
- если трек уже был отмечен как загруженный в Яндекс Музыку, повторное скачивание не должно сбрасывать этот статус;
- ошибки отдельных треков отображаются пользователю и не должны стирать уже сохранённый результат по другим трекам.

### 3.5 Скачивание с последующей загрузкой в Яндекс Музыку

Пользователь может выбрать режим «скачать и загрузить в Яндекс Музыку». В этом режиме приложение сначала сохраняет выбранные треки локально, затем отправляет доступные локальные файлы в указанный плейлист Яндекс Музыки.

Бизнес-правила:

- загрузка в Яндекс Музыку выполняется только при заданной ссылке на плейлист;
- загружать можно только в плейлист текущего аккаунта: ссылка на чужой плейлист отклоняется с понятным сообщением;
- перед загрузкой требуется действующая авторизация пользователя в Яндекс Музыке;
- успешная загрузка переводит трек в статус «в ЯМ»;
- если Яндекс Музыка приняла файл, но трек ещё обрабатывается и не виден в плейлисте, приложение сообщает об этом и предлагает сверить плейлист позже;
- если Яндекс Музыка отклоняет загрузку или меняет правила приёма файлов, локальные файлы и статусы скачивания должны сохраниться для повторной попытки.

### 3.6 Загрузка уже скачанных треков в Яндекс Музыку

Пользователь может отдельно запустить загрузку в Яндекс Музыку для треков, которые уже есть на диске и ещё не считаются загруженными.

Бизнес-правила:

- приложение берёт только локально существующие файлы;
- после успешной загрузки трек получает статус «в ЯМ»;
- повторно успешно загруженные файлы фиксируются в истории обработанных загрузок;
- если нет подходящих файлов, пользователь получает понятное сообщение.

### 3.7 Ручная отметка «уже в ЯМ»

Пользователь может вручную отметить выбранные треки как уже загруженные в Яндекс Музыку.

Сценарий нужен, когда:

- трек уже был добавлен в плейлист вручную;
- автоматическая загрузка недоступна;
- пользователь хочет синхронизировать локальный учёт без повторной отправки файла.

После ручной отметки трек получает статус «в ЯМ». Если у трека есть локальный файл, он также учитывается как уже обработанный для последующих загрузок.

### 3.8 Проверка Яндекс Музыки

В MVP пользователь может проверить:

- авторизован ли он в Яндекс Музыке;
- какой аккаунт используется для загрузки;
- сколько треков находится в выбранном плейлисте;
- какие локально отмеченные как «в ЯМ» треки не найдены в плейлисте;
- есть ли в плейлисте дубли или треки в обработке.

Эта проверка не меняет статусы автоматически. Она даёт пользователю информацию для решения: повторить загрузку, подождать обработки или вручную исправить статусы.

### 3.9 Остановка операции

Пользователь может остановить длительную операцию.

Правила остановки:

- уже скачанные или уже загруженные треки сохраняют свой статус;
- текущая операция завершается настолько быстро, насколько это позволяет внешний сервис;
- после остановки пользователь может повторить нужное действие.

## 4. Сущности и статусы

### 4.1 Трек

Трек в MVP содержит бизнес-данные:

- идентификатор SoundCloud;
- название;
- исполнитель;
- ссылка на SoundCloud;
- текущий статус;
- путь к локальному файлу, если он был скачан.

### 4.2 Статусы трека

| Статус | Смысл для пользователя |
|--------|-------------------------|
| `pending` | Трек найден в лайках SoundCloud и ещё не обработан |
| `downloaded` | Трек скачан на компьютер, но ещё не считается загруженным в Яндекс Музыку |
| `uploaded` | Трек считается загруженным в Яндекс Музыку или был вручную отмечен пользователем |
| `not_in_likes` | Трек был найден раньше, но больше не присутствует в текущих лайках SoundCloud |

### 4.3 Переходы статусов

| Событие | Изменение статуса |
|---------|-------------------|
| Новый трек найден при проверке лайков | `pending` |
| Трек успешно скачан | `pending` → `downloaded` |
| Трек успешно загружен в Яндекс Музыку | `downloaded` → `uploaded` |
| Пользователь вручную отметил трек как уже добавленный в Яндекс Музыку | `pending` / `downloaded` / `not_in_likes` → `uploaded` |
| Трек ожидал обработки, но пропал из текущих лайков SoundCloud | `pending` → `not_in_likes` |

Статус `uploaded` не должен автоматически понижаться при повторной проверке, скачивании или временных ошибках внешних сервисов.

## 5. Основные бизнес-процессы

### 5.1 Первый запуск

1. Пользователь запускает приложение.
2. В браузере открывается локальный интерфейс.
3. Пользователь вводит имя SoundCloud или ссылку на лайки.
4. При необходимости пользователь вводит ссылку на плейлист Яндекс Музыки.
5. Приложение сохраняет настройки для последующих запусков.

### 5.2 Обновление списка треков

1. Пользователь нажимает проверку SoundCloud.
2. Приложение получает актуальные лайки.
3. Приложение сравнивает лайки с локальным учётом.
4. Пользователь видит обновлённый список и количество новых треков.

### 5.3 Перенос новых треков на диск

1. Пользователь выбирает нужные треки.
2. Пользователь запускает скачивание.
3. Приложение сохраняет файлы в локальную музыкальную папку.
4. Успешные треки получают статус «на диске».
5. Ошибки показываются в журнале операции.

### 5.4 Перенос треков в Яндекс Музыку

1. Пользователь проверяет авторизацию Яндекс Музыки.
2. Пользователь выбирает режим загрузки в Яндекс Музыку.
3. Приложение отправляет локальные файлы в выбранный плейлист.
4. Успешные треки получают статус «в ЯМ».
5. Неподтверждённые или ошибочные загрузки остаются доступными для повторной попытки.

### 5.5 Сверка с плейлистом

1. Пользователь запускает сверку плейлиста.
2. Приложение сравнивает локально отмеченные треки с содержимым плейлиста.
3. Пользователь получает отчёт: найдено, отсутствует, дубли, треки в обработке.
4. Пользователь сам решает, какие действия выполнить после сверки.

---

## 6. Общие бизнес-правила

- В один момент времени выполняется только одна длительная операция: проверка, скачивание или загрузка.
- Любая операция должна показывать пользователю текущую фазу, прогресс и итог.
- Частичный успех сохраняется: уже скачанные и уже загруженные треки не теряются из учёта из-за последующей ошибки.
- Повторная загрузка трека, который уже есть в Яндекс Музыке, может создать дубль; интерфейс должен предупреждать пользователя перед таким действием.
- Локальный учёт используется как основа для предотвращения повторного скачивания и повторной загрузки.
- При недоступности SoundCloud или Яндекс Музыки пользователь должен получить понятное сообщение, а приложение должно сохранить уже полученный результат.
- Локальные музыкальные файлы по умолчанию остаются на компьютере после загрузки в Яндекс Музыку.

---

## 7. Данные и приватность

Данные пользователя хранятся локально на компьютере:

- настройки SoundCloud и Яндекс Музыки;
- локальный список треков и их статусы;
- история скачанных и загруженных файлов;
- скачанные аудиофайлы.

Приложение не требует собственного серверного аккаунта и не предназначено для коллективного доступа. Авторизация Яндекс Музыки используется с локальной машины пользователя.

---

## 8. Критерии готовности MVP

MVP считается соответствующим ТЗ, если:

- пользователь может сохранить SoundCloud-профиль и ссылку на плейлист Яндекс Музыки;
- проверка SoundCloud показывает актуальный список лайков и новые треки;
- выбранные треки скачиваются в локальную папку;
- уже скачанные треки не скачиваются повторно без необходимости;
- загрузка в Яндекс Музыку работает при корректной авторизации и доступном плейлисте;
- ошибки загрузки в Яндекс Музыку не удаляют локальные файлы и не мешают повторной попытке;
- ручная отметка «уже в ЯМ» корректно меняет статус выбранных треков;
- сверка плейлиста показывает найденные, отсутствующие, дублирующиеся и обрабатываемые треки;
- остановка операции сохраняет уже завершённые действия;
- пользователь видит итог операции и может продолжить работу без перезапуска приложения.
