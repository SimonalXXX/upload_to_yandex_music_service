# Спецификация фичи: состояние трека по трём признакам

**Статус:** согласовано
**Автор:** andravladix (с Claude)
**Дата:** 2026-10-01

---

## 1. Контекст и проблема

Один статус трека смешивал три независимых вопроса: есть ли файл на диске, есть ли трек в Яндекс
Музыке, лайкнут ли он на SoundCloud. Анализ 01.10 (302 трека): в медиатеке 8 разных сочетаний, а
показывалось 3 статуса. 298 треков выглядели одинаково «В ЯМ», хотя среди них: 70 и на диске, и в ЯМ;
34 отмечены «В ЯМ», но в плейлисте их нет; 9 разлайкнуты на SoundCloud.

---

## 2. Область (Scope)

### Входит

- Вместо поля `status` — три признака + ошибка:
  - **Диск** — есть ли файл (вычисляется по файловой системе);
  - **Яндекс Музыка** (`ym`): `none` не отправлен · `sent` ждёт ЯМ · `confirmed` в ЯМ (найден в
    плейлисте, с датой проверки) · `manual` отмечен вручную, не проверен · `missing` считался в ЯМ,
    но при проверке не найден · `rejected` ЯМ не принял (не появился за сутки) · `pinned` в ЯМ по
    подтверждению пользователя (проверка его не меняет);
  - **SoundCloud**: `liked` (в лайках / пропал из лайков / неизвестно) и `sc` (`ok` / `unavailable`
    с причиной — DRM, удалён, недоступен в стране);
  - `error` — последняя ошибка.
- Проверка по плейлисту записывает результат в `ym` (сверка, синхронизация, конец загрузки, фон).
- Отметка «пропал из лайков» — для всех треков, только информация.
- Несколько бейджей в строке трека; разделы боковой панели сгруппированы по признакам.
- Перенос существующей базы.

### Не входит

- Автоматическая повторная отправка `missing`/`rejected` (риск дубля, если сверка ошиблась из-за
  переименования трека в ЯМ) — только вручную.
- Автоматическое присвоение `confirmed` трекам `none`, найденным в плейлисте по названию (риск
  ложного совпадения).
- CLI.

## 3. Поведение

### 3.1 Переходы `ym`

| Событие | Переход |
|---------|---------|
| Загрузка, подтверждена по id | любое → `confirmed` |
| Загрузка, ЯМ принял файл | любое → `sent` (`sent_at`) |
| Проверка: трек найден в плейлисте | `sent` / `manual` / `missing` / `rejected` / `confirmed` → `confirmed` (`ym_checked_at`) |
| Проверка: не найден | `confirmed` / `manual` → `missing`; `missing` / `rejected` без изменений; `sent` → `rejected` через 24 ч |
| «Уже в ЯМ» | `none` / `sent` → `manual`; `missing` / `rejected` → `pinned` (пользователь знает лучше сверки) |
| «Снять «В ЯМ»» | любое → `none` (файл убирается из `upload_archive.txt`) |
| `pinned` | проверкой не меняется |

`sent` → `rejected` дополнительно записывает ошибку «ЯМ не принял трек: не появился в плейлисте за
сутки» и убирает файл из `upload_archive.txt`.

### 3.2 Проверка по плейлисту

Одна функция для всех мест: «Сверка», шаг сверки синхронизации, конец загрузки, фон. Фоновая — раз
в 15 минут и через ~30 с после запуска, если есть `sent` или `manual` и нет активной задачи.
Сопоставление — по исполнителю и названию, как раньше.

### 3.3 SoundCloud

Полная проверка лайков (без лимита `max_tracks`) ставит `liked` всем трекам базы: есть в выдаче →
в лайках, нет → пропал из лайков. С лимитом — только «в лайках» для найденных. `sc=unavailable`
ставится при неустранимой ошибке скачивания (как раньше `unavailable`), успешное ручное скачивание
возвращает `sc=ok`.

### 3.4 Что делают задачи

- Скачивание «новых» (синхронизация): нет файла, `ym=none`, `sc=ok`, не «пропал из лайков».
- Загрузка «всех готовых» (синхронизация): есть файл, `ym=none`.
- Явный выбор пользователя — как раньше; повторная отправка трека в состоянии `confirmed`,
  `pinned`, `manual`, `sent` требует подтверждения (возможен дубль).

### 3.5 Интерфейс

- Колонка «Состояние»: бейдж ЯМ (в ЯМ ✓ / ждёт / ⚠ нет в плейлисте / ✕ не принят / не проверен /
  новый / не в ЯМ), бейдж «На диске», пометка «не в лайках», бейдж «Недоступен» с причиной;
  подсказка с датой проверки.
- Боковая панель: **Медиатека** (все; новые — скачать; готовы к отправке — на диске, не в ЯМ),
  **Яндекс Музыка** (в ЯМ; ждут; ⚠ нет в плейлисте; не приняты; не проверены), **Диск** (на диске;
  только в ЯМ), **SoundCloud** (пропали из лайков; недоступные), **С ошибкой**. Пустые разделы,
  кроме основных, скрыты.
- Действия: «Уже в ЯМ» для `missing`/`rejected` = «считать в ЯМ» (`pinned`), с пояснением.
- Сверка: списки «⚠ нет в плейлисте» (загрузить заново / снять «В ЯМ» / считать в ЯМ),
  «не приняты ЯМ», «ждут появления».

## 5. Данные и миграции

`tracks.csv`: столбцы `sc_id, title, artist, sc_url, file, added, ym, ym_checked_at, sent_at, liked,
sc, sc_reason, error` (столбец `status` удаляется). Перенос при первом запуске, с копией
`tracks.before-states.csv`:

| Было `status` | `ym` | `liked` | `sc` |
|---------------|------|---------|------|
| `pending`, `downloaded` | `none` | в лайках | `ok` |
| `sent` | `sent` | неизвестно | `ok` |
| `uploaded` | `manual` → проверяется фоном через ~30 с | неизвестно | `ok` |
| `not_in_likes` | `none` | пропал из лайков | `ok` |
| `unavailable` | `none` | неизвестно | `unavailable` (причина из `error`) |

`liked` уточняется при ближайшей проверке лайков.

## 6. Критерии приёмки

1. Трек на диске и в ЯМ показывает оба бейджа.
2. После переноса и фоновой проверки 34 трека, которых нет в плейлисте, показываются «⚠ Нет в
   плейлисте», а не «В ЯМ»; найденные — «В ЯМ ✓» с датой проверки.
3. После проверки лайков разлайкнутые треки помечены «не в лайках».
4. «Уже в ЯМ» на «⚠ нет в плейлисте» переводит в «В ЯМ (подтверждено вами)», и сверка больше его
   не помечает.
5. Синхронизация не отправляет повторно «⚠ нет в плейлисте» и «не приняты ЯМ».
6. Разделы боковой панели и счётчики соответствуют признакам.

---

## 7. Риски и ограничения

- Сопоставление по названию: переименованный в ЯМ трек будет «⚠ нет в плейлисте» — для этого есть
  «Уже в ЯМ» → `pinned`.
- Фоновая проверка требует авторизации ЯМ (сервер из Терминала); без неё `manual` остаются
  непроверенными до успешной проверки.
- API 3.0.0 ломает старый формат `status` — старый интерфейс с новым сервером не работает
  (они поставляются вместе).
