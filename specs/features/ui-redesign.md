## 1. Контекст и проблема

Интерфейс MVP — одна страница, встроенная строкой в `web_app.py`. Часть возможностей системы в нём
недоступна (настройки, расписание), часть работает с изъянами:

- ошибки по трекам (в т.ч. DRM) не сохраняются — после перезагрузки трек снова «Новый»;
- сверка с плейлистом пишет итоги в журнал, с результатом ничего нельзя сделать;
- во время задачи блокируются поиск и фильтры, при скане список очищается;
- два разных принципа действий («по выбору» и «загрузить всё»);
- проверка ЯМ на каждое открытие страницы читает cookies Chrome.

Цель — интерфейс в духе приложений macOS, который закрывает эти пробелы и добавляет фоновую
синхронизацию, плеер и горячие клавиши.

## 2. Область (Scope)

### Входит

| ID | Требование |
|----|------------|
| Н-01 | Экран настроек: все параметры `config.yaml`, кроме CLI-only; профиль SoundCloud и плейлист ЯМ проверяются при вводе |
| Н-02 | Первый запуск по шагам: SoundCloud → Яндекс Музыка → первая проверка лайков |
| Н-03 | Статус `unavailable` (DRM, удалён, недоступен в стране) с причиной; последняя ошибка трека сохраняется |
| Н-04 | Фильтры по всем статусам со счётчиками; сортировка по дате добавления, исполнителю, названию |
| Н-05 | Весь список без «Показать ещё» (виртуализация строк) |
| Н-06 | Интерфейс не блокируется во время задачи; при скане список не очищается |
| Н-07 | Действия всегда над выбранными; быстрые выборки «все новые / все на диске / все ненайденные в ЯМ» |
| Н-08 | Действия с треком: открыть на SoundCloud, показать в Finder, послушать |
| Н-09 | Сверка с ЯМ — отдельный экран: «нет в плейлисте» (загрузить заново / снять отметку), дубли, в обработке |
| Н-10 | Остановка проверки лайков |
| Н-11 | История операций (последние 50) с итогами и журналом |
| М-01 | Автосинхронизация по расписанию внутри приложения (по умолчанию выключена) + уведомления macOS |
| М-02 | «Синхронизировать» одной кнопкой: проверить → скачать новые → загрузить в ЯМ → сверить |
| М-03 | Встроенный плеер скачанных треков |
| М-04 | Горячие клавиши |
| М-05 | Светлая/тёмная тема по системе; прогресс задачи в заголовке вкладки |
| М-06 | Установка как приложение (web app manifest) |
| М-07 | Список дублей в плейлисте ЯМ — **только показ** |

### Не входит

- Удаление дублей из плейлиста ЯМ (отдельная фича — меняет данные в ЯМ).
- Изменения CLI (`sc_downloader.py`, `ym_uploader.py` как CLI). Секция `schedule` в `config.yaml`
  остаётся за CLI; автосинхронизация веб-приложения — отдельная секция `autosync`.
- Service worker / офлайн-кэш (для установки как приложения не требуется).
- Сборка фронтенда (Node на машине нет): обычные ES-модули и CSS.

## 3. Поведение

### 3.1 Раскладка и стиль

- Окно: боковая панель (разделы) + основная область (панель инструментов, список) + нижняя панель
  плеера. При ширине < 760 px боковая панель сворачивается в выпадающее меню.
- Стиль macOS: системный шрифт, цвета Apple HIG (label/secondary/separator), акцент — розовый
  Apple Music; светлая и тёмная тема по `prefers-color-scheme`; полупрозрачная боковая панель.
- Разделы боковой панели:
  - **Медиатека:** Все, Новые, На диске, В ЯМ, Не в ЯМ, Пропали из лайков, Недоступные, С ошибкой — со счётчиками.
  - **Яндекс Музыка:** Сверка (с числом ненайденных после последней сверки).
  - **История**, **Настройки**.
- В подвале боковой панели — статус ЯМ (логин или ошибка) и время следующей автосинхронизации.

### 3.2 Медиатека

- Строка трека: галочка, название, исполнитель, дата добавления, статус, действия при наведении
  (▶ послушать — если есть файл; меню ⋯: открыть на SoundCloud, показать в Finder, уже в ЯМ /
  снять отметку «В ЯМ»).
- Исполнителя у нового трека нет до скачивания (плоский скан SoundCloud его не отдаёт) — вместо
  него показывается `@автор-из-ссылки` приглушённым цветом.
- Статусы: Новый, На диске, В ЯМ, Пропал из лайков, Недоступен (причина во всплывающей подсказке).
  Если у трека сохранена последняя ошибка — красная точка с текстом ошибки в подсказке.
- Во время задачи у трека показывается живой статус: «Скачивается», «Конвертация», «Отправка в ЯМ».
- Выбор: клик по галочке; Shift+клик — диапазон; «выбрать всё» — все треки текущего фильтра
  с подписью «Выбрано N из текущего списка».
- Быстрые выборки (меню «Выбрать»): все новые, все на диске, все ненайденные в ЯМ (после сверки).
- Панель выбора (внизу, пока выбор не пуст): «Скачать», «Скачать и в ЯМ», «Загрузить в ЯМ»
  (только треки с файлами), «Уже в ЯМ», «Снять отметку «В ЯМ»», «Снять выбор». Действия, которые
  создадут дубль в ЯМ, требуют подтверждения с числом таких треков.
- Поиск (название, исполнитель, автор из ссылки) и фильтры работают во время любой задачи.
  Скан обновляет список по завершении, не очищая его.

### 3.3 Задачи и прогресс

- В панели инструментов — индикатор задачи: название фазы, прогресс N/M, текущий трек, «Остановить».
  Клик раскрывает живой журнал задачи.
- Задачи: «Проверить лайки», «Синхронизировать», скачивание/загрузка выбранных, автосинхронизация.
  Одновременно выполняется одна задача; кнопки запуска других задач неактивны.
- Проверка лайков показывает «Получено N» и может быть остановлена (Н-10).
- По завершении — уведомление внизу окна с итогом; ошибки — красным, частичный успех — оранжевым.
- Заголовок вкладки во время задачи: `42% · Скачивание — Музыкальный`.
- Если страница переподключилась (сон, обрыв), состояние восстанавливается по событию `hello`
  и перечитыванию списка.

### 3.4 Синхронизация (М-02) и автосинхронизация (М-01)

- «Синхронизировать» = шаги: проверить лайки → скачать все `pending` → загрузить в ЯМ все
  `downloaded` (если задан плейлист и есть авторизация) → сверить плейлист. Итог: новых N,
  скачано, загружено, ошибок, ненайденных в плейлисте.
- Автосинхронизация (`autosync` в `config.yaml`): `enabled` (по умолчанию `false`), `interval_hours`
  (1/3/6/12/24), `download`, `upload`, `notify`. Выполняется тем же сценарием, что «Синхронизировать»,
  с учётом `download`/`upload`. Следующий запуск = начало последнего автозапуска + интервал; если
  автозапусков ещё не было — в течение минуты после включения. Если в момент запуска идёт другая
  задача — запуск откладывается до освобождения. Работает, пока открыт `Запуск.command`.
- Уведомление macOS после автосинхронизации (при `notify`): если есть новые треки, загруженные или
  ошибки. Без изменений — без уведомления.

### 3.5 Сверка с ЯМ (Н-09, М-07)

- Экран «Сверка»: кнопка «Сверить сейчас», время последней сверки, итоги (в плейлисте, найдено,
  нет в плейлисте, дубли, в обработке).
- «Нет в плейлисте» — список с галочками; действия «Загрузить заново» (есть файл → загрузка;
  нет файла → скачать и загрузить) и «Снять отметку «В ЯМ»».
- «Дубли» — список «исполнитель — название × N», только просмотр.
- «В обработке» — список треков плейлиста, ещё недоступных для прослушивания.

### 3.6 Настройки (Н-01) и первый запуск (Н-02)

- Разделы: SoundCloud (имя/ссылка, лимит числа лайков, пауза между запросами, cookies браузера),
  Яндекс Музыка (статус авторизации + «Проверить снова», ссылка на плейлист, пауза между загрузками,
  удалять файл после подтверждённой загрузки), Файлы (папка, формат, битрейт, «Открыть в Finder»),
  Автосинхронизация (вкл., интервал, скачивать, загружать, уведомлять, время следующего запуска).
- Профиль SoundCloud проверяется при вводе (с задержкой): «✓ Имя · N лайков» или «Профиль не найден».
  Плейлист ЯМ: «✓ Название · N треков» или ошибка (чужой плейлист, не найден, нет авторизации).
- Сохранение — кнопкой «Сохранить», активной при изменениях; невалидные поля не блокируют
  сохранение остальных, но подсвечиваются.
- Первый запуск (не задан профиль SoundCloud): мастер из 3 шагов —
  1) имя SoundCloud (проверка); 2) Яндекс Музыка: проверка доступа (с подсказкой про «Полный доступ
  к диску» для Терминала) и ссылка на плейлист — шаг можно пропустить; 3) «Проверить лайки».

### 3.7 Плеер (М-03)

- Нижняя панель: ▶/⏸, ◀◀/▶▶ (по текущему списку среди треков с файлами), название, исполнитель,
  перемотка, время. Скрыта, пока ничего не играло.
- Источник — локальный файл трека (`GET /api/tracks/{id}/audio`, поддержка Range для перемотки).

### 3.8 Горячие клавиши (М-04)

| Клавиши | Действие |
|---------|----------|
| ⌘F | поиск |
| ⌘A | выбрать все треки текущего списка (вне полей ввода) |
| ↑ / ↓ | перемещение по списку |
| Shift+↑/↓ | расширить выбор |
| X или Enter | отметить трек под курсором |
| Пробел | играть / пауза (трек под курсором или текущий) |
| ⌘. | остановить задачу (стандарт macOS для «Отменить»; вместо Esc — чтобы не прервать длинную задачу случайно) |
| Esc | закрыть диалог / меню, иначе снять выбор |
| ⌘R | синхронизировать (в приложении; в браузере не перехватывается) |

### 3.9 История (Н-11)

- Последние 50 операций: время, тип, источник (вручную / автоматически), итог, статус
  (успех / остановлено / ошибка). Раскрытие — журнал операции (до 300 записей).
- Хранится в `history.json` в папке проекта.

## 6. Критерии приёмки

1. Все сценарии разделов 3.2–3.9 выполняются в Safari и Chrome (последние версии) на macOS.
2. Трек под DRM после неудачной попытки получает «Недоступен» с причиной и остаётся таким после
   перезагрузки и повторной проверки лайков.
3. Во время скачивания работают поиск, фильтры, сортировка, переключение разделов.
4. Скан можно остановить; список до скана остаётся видимым.
5. Сверка показывает ненайденные; их можно выбрать и загрузить заново или снять отметку.
6. «Синхронизировать» проходит все шаги и выдаёт итог; автосинхронизация запускается по расписанию
   и присылает уведомление macOS.
7. Плеер воспроизводит и перематывает скачанный трек.
8. Горячие клавиши из 3.8 работают; всё управляется с клавиатуры.
9. Тема следует системной; при 5000 строках прокрутка плавная.
10. Приложение устанавливается из Chrome («Установить приложение») и открывается в отдельном окне.

## 7. Риски и ограничения

- Проверка профиля SoundCloud использует внутренний метод экстрактора yt-dlp (`_call_api`) —
  может сломаться при обновлении yt-dlp; при сбое — упрощённая проверка (существование профиля без
  числа лайков).
- Авторизация ЯМ требует «Полного доступа к диску» для Терминала; сервер, запущенный не из
  Терминала, не видит cookies Chrome.
- Автосинхронизация работает, только пока запущено приложение (`Запуск.command`).
- Уведомления macOS идут через `osascript` — при первом показе macOS может спросить разрешение
  для «Редактора скриптов».
