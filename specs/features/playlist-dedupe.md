# Спецификация фичи: удаление дублей в плейлисте Яндекс Музыки

**Статус:** согласовано
**Автор:** andravladix (с Claude)
**Дата:** 2026-10-18

---

## 1. Контекст и проблема

В плейлисте накопились дубли (80+ групп; часть появилась из-за повторных отправок — см. `upload-confirmation.md`,
дубли 16.10). Удалять их вручную в Яндекс Музыке долго. Сверка до сих пор показывала дубли только списком.

---

## 2. Область (Scope)

### Входит

- Поиск групп дублей: одинаковые исполнитель + название (с версией) + длительность (±1 с).
- Предпросмотр: для каждой группы — какую копию оставляем (самую раннюю по времени добавления),
  какие удаляем.
- Удаление выбранных групп (лишних копий) из плейлиста через `playlists/{kind}/change` (операция
  `delete`, с текущей ревизией плейлиста). Остаётся ровно одна копия в группе.
- Резервная копия плейлиста (id, исполнитель, название, длительность, время добавления) в
  `backups/playlist-<время>.json` перед каждым удалением.
- Проверка результата: после удаления плейлист перечитывается; число треков должно уменьшиться
  ровно на число удалённых, оставляемые копии — на месте.

### Не входит

- Автоматическое удаление без выбора пользователя (удаление — только по явной кнопке и подтверждению).
- Удаление загруженных файлов из «Моей коллекции» ЯМ; изменение чужих плейлистов.
- Откат: удалённый из плейлиста загруженный трек вернуть без повторной загрузки нельзя
  (резервная копия — для сверки, не для восстановления).

---

## 3. Поведение

- `GET /api/playlist/duplicates` — группы дублей текущего плейлиста (читает ЯМ, ничего не меняет).
- `POST /api/playlist/dedupe` с `{"keep_ids": [...]}` — удалить лишние копии **только** в группах,
  оставляемая копия которых указана. Без списка не работает (нет режима «удалить всё»).
  Требует отсутствия активной задачи; плейлист читается заново, группы пересчитываются.
- Интерфейс («Сверка» → «Дубли в плейлисте»): кнопка «Найти лишние копии», список групп с галочками и
  пометкой «останется / удалится», кнопка «Удалить лишние копии (N)» с подтверждением «Это необратимо».
- Если ревизия плейлиста изменилась между чтением и записью (параллельное изменение) — отказ с
  просьбой повторить.

## 6. Критерии приёмки

1. Предпросмотр показывает группы и оставляемую копию, ничего не меняя в ЯМ.
2. Удаление одной группы убирает ровно лишние копии, оставляя самую раннюю; остальной плейлист цел.
3. Перед удалением создана резервная копия; после — проверка результата.
4. Без `keep_ids` или при активной задаче удаление не выполняется.

---

## 7. Риски и ограничения

- Интерфейс `change` неофициальный и может измениться; сбой не должен оставлять плейлист в
  промежуточном состоянии: удаление идёт одной операцией с ревизией, результат проверяется.
- Два разных трека с одинаковыми названием и длительностью будут сочтены дублями — поэтому в списке
  видны оба и удаление идёт по выбору пользователя.
