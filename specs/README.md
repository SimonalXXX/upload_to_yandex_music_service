# Spec-Driven Development (SDD) — процесс для репозитория «Музыкальный»

Здесь лежит **нормативная документация**: спецификации должны опережать или сопровождать код так, чтобы любой участник (или агент) мог проверить соответствие реализации бизнес-логике и контрактам.

## Иерархия документов

| Документ | Роль |
|----------|------|
| [`SDD.md`](../SDD.md) | Единое ТЗ MVP: бизнес-логика, сценарии, сущности и правила статусов |
| [`openapi.yaml`](./openapi.yaml) | Контракт HTTP REST API (`web_app.py`), машиночитаемый |
| [`sse-events.md`](./sse-events.md) | Контракт событий `/api/progress` (SSE), типы и поля JSON |
| [`cli-contract.md`](./cli-contract.md) | Контракт CLI (`sc_downloader.py`, `ym_uploader.py`) |
| [`templates/feature-spec.md`](./templates/feature-spec.md) | Шаблон спецификации новой возможности |
| [`features/ui-redesign.md`](./features/ui-redesign.md) | Новый интерфейс: раскладка, синхронизация, плеер, горячие клавиши, критерии приёмки |

При противоречии приоритет такой: **спецификация API/SSE в `specs/` → код → SDD**, если явно не решено иначе в PR.

## Цикл работы (Spec → Implement → Sync)

1. **Идея / задача** — кратко в Issue или в заголовке PR.
2. **Спецификация** — для заметного поведения:
   - обновить или добавить раздел в `openapi.yaml` / `sse-events.md` / `cli-contract.md`;
   - при новой фиче заполнить копию [`templates/feature-spec.md`](./templates/feature-spec.md) в `specs/features/<краткое-имя>.md` (папку `features/` можно создать при первой фиче).
3. **Реализация** — код следует утверждённым полям, кодам ответов и типам событий.
4. **Синхронизация** — после мержа обновить [`SDD.md`](../SDD.md), если изменилась бизнес-логика, пользовательский сценарий или правила статусов.

## Правила изменений

- Ломающее изменение API: поднять версию в описании OpenAPI (`info.version`) и явно описать миграцию в теле PR.
- Новое поле в JSON ответа — объявить в `openapi.yaml` или в `sse-events.md`.
- Поведение «по договорённости только в коде» избегать: либо дописать спеку, либо пометить в спеке как `deprecated` / внутреннее.

## Проверка соответствия

Вручную:

- REST: сверить маршруты в `web_app.py` с `openapi.yaml`.
- SSE: сверить `_broadcast({...})` в `web_app.py` и `handleEvent` в `static/js/tasks.js` с `sse-events.md`.

При желании можно подключить линтер OpenAPI (`spectral`) в CI — в репозитории пока не обязательно.

## Связь с пользовательской документацией

- [`README.md`](../README.md) остаётся **руководством пользователя** (установка, кнопки).
- `SDD.md` и `specs/` — **для разработчиков и сопровождения**.
